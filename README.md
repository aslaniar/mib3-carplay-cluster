# MIB3 CarPlay Cluster

This is a mod that will allow for CarPlay to be extended to run inside the VW Digital Cockpit, ALONGSIDE the main screen, taking over the car's native map and painting CarPlay's map instead.

It takes over the head unit's stream to the cluster and replaces it with the alt stream generated by your iPhone. That stream is what gets painted onto the cluster. 

> [!NOTE]
> This is a working product, and it is still in active development. The delivery system, which will install the mod without a root shell, is not finished yet. Until it is, you need a root shell on your head unit to try the mod.

Upcoming features: 
 - Non-root installation
 - Persistence
 - UI options (enable/disable, direction cards, etc.)

## What it does

| | |
| --- | --- |
| **Shim** | Interposes three CarPlay library seams inside the running `carplay` process, advertises a second display (type 111) for the cluster, receives that stream, decrypts it, and hands access units to a socket. |
| **Sender** | Re-muxes each access unit into MPEG-TS and paces it onto the cluster's RTP multicast, sending the video through the car's internal Ethernet bus. |
| **Supervisor** | One resident process/daemon. When the phone starts streaming it takes the cluster's UDP port; when the session ends it hands the port back to the car.  |


## Requirements

**Root on the head unit.** The shim is loaded into a live `carplay` with `ptrace` +
`dlopen` + GOT-slot patching. That requires privilege, and there is no way around it.

This repository **does not contain, describe, or require any method of obtaining root**.
`up.sh` opens by demanding a root shell and exits if it does not have one. 

Tested on VW MIB3 (LG), train `MOI3_EU_VW_R8830L_MU0883`, part `3G8919360AR`. Other trains are CURRENTLY untested.

Nothing is persistent: `/tmp` and `/dev/shm` are all it writes, and a reboot clears
everything. You will have to rerun up.sh on each boot to use the mod. Persistence is currently being worked on. 

## Layout

```
up.sh                  the one-command bring-up (root required)
src/shim/              the interposer: three seams, type-111 advert, receiver, decrypt
src/sender/            Path B sender: re-mux to MPEG-TS and pace onto the cluster feed
src/wheel/             steering-wheel zoom tap (read-only RSI watcher)
src/control/           the resident supervisor, its CLI, and the RSI handover
src/inject/            ptrace + dlopen loader for the live carplay
tools/                 analysis: PES/TS extraction, SPS dump, AU boundary checks, reports
tests/                 the benches, plus the H.264 fixture they replay
bin/                   the pinned aarch64 builds the tests and up.sh expect
docs/                  
```

## Build

The head unit runs aarch64 with its own glibc (≤ 2.23) and ships no CRT, so every tool has its
own `_start` and is linked `-nostdlib` against the unit's libs.

Compiled binaries are located in bin/. Should you want to build src yourself, instructions are below. Clang and lld are required to build. 

```sh
sh src/shim/build.sh     # -> bin/mib3shim.so
sh tools/build.sh        # -> bin/mib3clusterstream, bin/mib3wheel
```

## Install

```sh
# copy this tree to a flash drive in your center console, then from a root shell:
sh up.sh
```

`up.sh` stages the kit into `/tmp/kit`, checks the md5 of all three pinned binaries,
injects the shim into the running CarPlay, and starts the supervisor. Re-runnable.

```sh
sh /tmp/kit/pathbctl status     # what the supervisor is doing, and why
sh /tmp/kit/pathbctl release    # hand the cluster back to the car
sh /tmp/kit/pathbctl stop       # stop the supervisor
```
